# Орбита

Личный календарь для учёбы и дел вне неё. В календаре можно хранить дедлайны, события с датой и временем, ежегодные дни рождения и запланированные шаги. В первой сессии реализован календарь с обычными записями. Галерея планов и сценарий назначения шага доступны в [кликабельном макете](design/prototype.html).

## Запуск в PowerShell

Проверено на Windows с Node.js 24.14.1, npm 11.11.0 и Python 3.14.4. Команды выполняются из корня Orbit.

```powershell
npm run setup
npm run seed
npm run dev
```

Откройте [календарь](http://127.0.0.1:5173/calendar). Vite на порту 5173 проксирует `/api` в FastAPI на порту 8000. Интерактивное описание запросов доступно в [FastAPI Docs](http://127.0.0.1:8000/docs).

SQLite по умолчанию хранится в `.data/orbit.sqlite3`. `ORBIT_DB` задаёт другой путь. `npm run seed` добавляет демонстрационные записи на текущий месяц по локальным часам. Для месяца из макета подходит `npm run seed -- --date 2026-11-20`. Уже существующие записи seed сохраняет. Данные браузерных тестов пишутся в отдельную временную SQLite.

## Сценарий календаря

1. Откройте [27 ноября 2026](http://127.0.0.1:5173/calendar?date=2026-11-27). Добавьте событие «Поездка в Карелию», оставив начало 27 ноября и установив окончание 2 декабря. Для ручного создания на чистых данных начните с пустой базы. После seed поездка уже есть.
2. Выберите 28 ноября и перезагрузите страницу. В повестке будет «27 ноя — 2 дек · день 2 из 6». Чтобы посмотреть тот же сценарий, что в макете, откройте [28 ноября](http://127.0.0.1:5173/calendar?date=2026-11-28).
3. Перейдите на декабрь стрелкой месяца. Первого декабря в повестке будет «день 5 из 6». Откройте запись и поменяйте окончание на 4 декабря. После сохранения и перезагрузки повестка покажет «день 5 из 8».
4. С клавиатуры перейдите Tab на календарь, выберите дату стрелками и нажмите Enter. Из повестки можно открыть любую запись. Escape закрывает диалог и возвращает фокус на кнопку, которая его открыла.

## Макет и реализация

[Автономный макет](design/prototype.html) открывается напрямую из файла. Полоса «Состояния макета» под календарём открывает пустой день, выбор шага, заполненную форму, ожидание, успех, ошибку и экран плана. В макете можно назначить «Собрать черновик» на 21 ноября, отметить его выполненным и увидеть `2 из 3` в плане.

В ТЗ для макета заданы два действия. Можно назначить шаг из плана или выбрать его из свободного дня. AI предложил разворот с повесткой справа и одинаковыми полосами поездки в двух неделях. На первом просмотре при 390×844 кнопка добавления переносилась на отдельную строку, а карточка повестки начиналась слишком низко. После просмотра уменьшил высоту строк месяца и собрал верхнюю панель в одну строку при 390 px. На широком экране также сократил высоту недель, чтобы было видно продолжение поездки.

В макете автономные системные шрифты, в реализации Inter и PT Serif локально с кириллицей. В рабочем месяце сводка склоняется по-русски, а у продолжения поездки есть метка на краю полосы. Снимки реализации получены с фиксированной демобазой и настоящим FastAPI.

| Где | Что используется |
| --- | --- |
| [Тема](frontend/src/app/theme.ts) | `MantineProvider`, цвета и типографика |
| [Календарь](frontend/src/features/calendar/CalendarPage.tsx) | `Button`, `ActionIcon`, `NativeSelect`, `Alert` |
| [Повестка](frontend/src/features/calendar/Agenda.tsx) | `Card`, `Button`, `Skeleton` |
| [Форма](frontend/src/features/calendar/EntryDialog.tsx) | `Modal`, `TextInput`, `NativeSelect`, `Checkbox`, `Button`, `Alert` |
| [Сетка](frontend/src/features/calendar/MonthGrid.tsx) | CSS Grid, клавиатурный курсор, недельные сегменты |
| [API и схема](server/main.py) | FastAPI и SQLite, запись и проверка полей, выборка по пересечению |

Запрос на интерфейс в ТЗ требовал «из Mantine взять Button, ActionIcon, TextInput, NativeSelect/Select, Checkbox, Card, Modal, Alert, Skeleton». После клавиатурной проверки добавил явный возврат фокуса при закрытии. Запрос на тесты требовал удержать POST незавершённым и воспроизвести двойной клик и повторный Enter отдельно. В общем тесте состояний дополнительно проверяется сбой перечитывания после успешного POST. Интерфейс показывает успех записи и даёт повторить загрузку календаря.
